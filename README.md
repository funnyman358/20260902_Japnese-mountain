# ヤマコンプ ⛰️

日本全国の「登れる山」674座を収録した、登頂記録＆コンプリート達成アプリです。
登った山にチェックを入れるだけで、コンプリート率・レベル・称号・実績バッジ・都道府県マップが育っていきます。

スマートフォンでもPCでも使え、「同期キー」を使えば端末間で記録を共有できます。

## 主な機能

### 記録する
- ワンタップで登頂チェック（同じ山に何度でも記録可）
- 日付・天気・同行者・思い出度(★5)・メモを残せる登山記録
- 「行きたい山」リスト（🚩）

### コンプリートを目指す
- **全674座に対する登頂数とコンプリート率**を常に表示
- 累積標高がそのまま経験値になる**レベル制**（Lv.1〜）
- 登頂数に応じて上がる**14段階の称号**（ふもとの旅人 → 日本山岳王）
- **68個の実績バッジ**（登頂数／名山リスト／エリア制覇／標高／チャレンジ／記録習慣）
- 「あと◯座で解除」が常に見える次の目標表示
- 47都道府県タイルマップでの登頂率ヒートマップ、県・地方コンプリート
- 累積標高を「富士山◯回分」「エベレスト◯回分」に換算
- 年別・月別の登山ペース、自己ベスト、連続登山月数
- 記録をテキストで共有／コピー

### 探す（多軸フィルタ）
山名・よみ・都道府県・市町村のフリーワード検索に加えて、以下を自由に組み合わせられます。

| 軸 | 内容 |
| --- | --- |
| 登頂状況 | すべて／未登頂／登頂済／行きたい |
| 地方 | 北海道〜九州・沖縄の10地方 |
| 都道府県 | 47都道府県（複数選択可） |
| 名山リスト | 日本百名山／二百名山／三百名山／花の百名山／都道府県最高峰 |
| 山の種類・特徴 | 火山・活火山・独立峰・岩稜・アルプス・原生林・高原・湿原・カルスト・信仰・花・紅葉・樹氷・大展望・縦走・海の眺望・温泉・世界遺産・里山・沢 |
| 標高帯 | 〜1000m／1000-1500／1500-2000／2000-2500／2500-3000／3000m以上 |
| 難易度 | 体力度・技術度（各5段階の上限指定） |
| 適期 | 春・夏・秋・冬 |
| 行程 | 半日／日帰り／1泊2日／2泊以上、ロープウェイ等の有無 |
| 並び替え | 標高順／五十音順／やさしい順／手ごわい順／都道府県順 |

各山の詳細ページでは、**所在する都道府県と市町村**、山域、標高、体力度・技術度、適期、標準的な行程、特徴タグ、その山の登頂記録、近くの似た山を確認できます。

## 収録データについて

- **674座**（日本百名山100座と3,000m峰21座を全収録／二百名山・三百名山・花の百名山・都道府県最高峰を含む）
- **47都道府県すべて**に最低5座以上、各県の代表的な登山対象を収録
- 各山に「山名・よみ・標高・都道府県・市町村・山域・選定リスト・特徴タグ・体力度・技術度・適期・行程・ロープウェイ有無・紹介文」を収録
- データは `src/data/mountains/*.ts` にあり、`npm run validate` で整合性を検査できます

> データは一般に知られている情報をもとに整理したものです。実際の登山では最新の地図・自治体や山小屋の情報・気象条件を必ずご確認ください。活火山は噴火警戒レベルにより規制が変わります。

## 端末間の同期のしくみ

メールアドレスもパスワードも不要の「同期キー」方式です。

1. 1台目の端末で「アカウント」→「同期を開始してキーを発行」
2. 表示された同期キー（例 `7xcvx-jfjs4-c3ju2-nygpj`）をコピー、または参加リンクをコピー
3. 2台目の端末でキーを入力（または参加リンクを開く）
4. 以後、両方の端末で自動的に記録がひとつにまとまります

- ローカルファースト設計です。オフラインでも記録でき、オンラインになったときに同期します。
- 同じレコードは「更新時刻が新しい方」を採用し、削除も端末間で反映されます（削除フラグ方式）。
- 同期キーは約99ビットのランダム文字列です。データベースのテーブルには直接アクセスできない設定（RLS + SECURITY DEFINER 関数）になっており、**キーを知っている人だけ**が読み書きできます。キーは他人に教えないでください。
- 同期を使わなくてもアプリはローカル保存だけで完全に動作します。バックアップの書き出し／読み込み（JSON）も利用できます。

## 技術構成

- Next.js 16（App Router、静的生成）／React 19／TypeScript
- Tailwind CSS v4（ライト・ダーク自動対応）
- Zustand（localStorage 永続化）
- Supabase（Postgres + RPC。認証なしの同期キー方式）
- PWA（manifest + Service Worker、ホーム画面追加・オフライン起動対応）

## 開発

```bash
npm install
npm run dev        # http://localhost:3000
npm run check      # データ検証 + 型チェック + Lint
npm run build      # 本番ビルド（山の詳細ページ674件を静的生成）
```

環境変数（`.env.local` または Vercel の環境変数）:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxx
```

未設定の場合、同期機能だけが無効になり、他の機能はそのまま動作します。
`.env.production` には公開しても安全な publishable key のみを含めており、そのままデプロイできます。

## Vercel へのデプロイ

1. [vercel.com/new](https://vercel.com/new) を開く
2. このリポジトリ（`funnyman358/20260902_japnese-mountain`）をインポート
3. Framework Preset は自動で **Next.js** が選択されます。設定はそのままで **Deploy**
4. 完了後に発行される URL をスマホでも開き、ブラウザの「ホーム画面に追加」でアプリとして使えます

環境変数はリポジトリの `.env.production` に含まれているため追加設定は不要です。
別の Supabase プロジェクトを使う場合のみ、Vercel の環境変数で上書きしてください。

## データベース（Supabase）

`supabase/migrations/` に適用済みのスキーマを置いています。

- `sync_vaults` テーブル：同期キーごとの保管庫（RLS 有効・ポリシーなし＝直接アクセス不可）
- `vault_pull(p_key)` / `vault_push(p_key, p_payload, p_expected)`：SECURITY DEFINER の RPC。
  キーの形式検証・サイズ上限・楽観的ロック（競合検知）を行います。
